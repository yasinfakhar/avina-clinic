# خروجی آزمایشی آوینا برای Windows 7

برنچ: `codex/windows7-legacy`

این مسیر ساخت مستقل است: UI و routeهای API از کد اصلی خوانده می‌شوند؛ در
خروجی قدیمی Next.js اجرا نمی‌شود. سرور loopback در `legacy/server.cjs`
همان handlerها را با Request/Response و پارامترهای مسیر اجرا می‌کند.
Electron روی 22.3.27 ثابت شده و `node:sqlite` هنگام bundle با
`better-sqlite3` جایگزین می‌شود. Node جدید فقط روی کامپیوتر سازنده لازم است.

## پیش‌نیاز دستگاه مقصد

- Windows 7 SP1 **64-bit** با به‌روزرسانی‌های لازم برای SHA-2 و TLS.
- Microsoft .NET Framework 4.8 و Windows Management Framework 5.1؛
  بکاپ فعلی از PowerShell و System.IO.Compression استفاده می‌کند.
- برای فعال‌سازی/بررسی دورهٔ آزمایشی اتصال به سرویس لایسنس لازم است.

نصاب وجود .NET 4.8 و PowerShell 5.1 را بررسی می‌کند. نصب SP1 و صحت ارتباط
TLS باید در ماشین مقصد بررسی شود. Electron 22 دیگر پشتیبانی امنیتی ندارد؛
این خروجی را تا تکمیل تست روی ماشین ویندوز ۷، نسخهٔ تأییدشده اعلام نکنید.

## ساخت روی Windows 10/11

Node.js 22.13 یا جدیدتر، وابستگی‌های عادی پروژه و دسترسی دانلود npm/Electron
لازم است. اگر SQLite باینری آماده نداشته باشد، Python و Visual Studio Build
Tools با گزینهٔ Desktop development with C++ هم لازم می‌شوند.

```powershell
git switch codex/windows7-legacy
npm ci
npm --prefix legacy ci --ignore-scripts --no-audit --no-fund
node legacy/node_modules/electron/install.js
npm run build:win7
```

دستور `npm ci` برای checkout تازه است؛ در محیط توسعهٔ موجودی که وابستگی‌ها
نصب هستند لازم نیست دوباره اجرا شود. وابستگی‌های قدیمی در `legacy/node_modules`
نصب می‌شوند و Electron اصلی پروژه تغییر نمی‌کند. lockfile مخصوص این خروجی
در `legacy/package-lock.json` وجود دارد و باید همراه تغییرات نگه داشته شود.

در `.env.desktop`، `LICENSE_SERVICE_URL` با HTTPS، `LICENSE_PUBLIC_KEY` و
`INITIAL_ADMIN_PASSWORD` را تنظیم کنید؛ یا فایل محلی
`electron/release-config.json` آماده داشته باشید. اسکریپت هیچ‌کدام از این
مقادیر را چاپ نمی‌کند. اگر فایل قبلی رمز مدیر داشته باشد حفظ می‌شود؛ در غیر
این صورت مقدار پیش‌فرض کد اصلی اعمال می‌شود. برای انتشار رمز اختصاصی بگذارید.
برای امضای خروجی، تنظیمات معمول `CSC_LINK` و `CSC_KEY_PASSWORD` را نیز بدهید.

خروجی نصاب:

```text
release-win7/Avina-Audiology-Win7-Setup-<version>.exe
```

خروجی پوشه‌ای برای بررسی سریع:

```powershell
npm run build:win7:dir
node scripts/verify-windows7.mjs
```

برای بررسی همین سناریوها با وابستگی‌های داخل بستهٔ نهایی:

```powershell
node scripts/verify-windows7.mjs --packaged
```

برای تست خودکار نمایش صفحهٔ ورود در Chromium 108 (روی یک session دسکتاپ
که اجرای رابط گرافیکی Electron را اجازه می‌دهد):

```powershell
node scripts/verify-windows7.mjs --ui
```

در صورت موفقیت، تصویر `release-win7/win7-login-smoke.png` هم ساخته می‌شود.
اجرای این گزینه در محیط فعلی موفق نشد؛ تست‌های سرور مستقل از آن اجرا می‌شوند.

## نتیجهٔ بررسی فعلی

- نصاب امضاشدهٔ نسخهٔ 1.1.14 ساخته شد.
- بررسی Authenticode روی این سیستم، ریشهٔ زنجیرهٔ گواهی فعلی را غیرقابل اعتماد
  گزارش کرد؛ وجود امضا به معنی اعتماد خودکار ویندوز به این گواهی نیست.
- تست ورود، کنترل دسترسی، SQLite، مسیر پویا، multipart PDF و توقف امن، هم
  از staging و هم از داخل `app.asar` بستهٔ نهایی با Electron 22 موفق بود.
- تست خودکار UI در این محیط با خروج زودهنگام Electron شکست خورد؛ علت آن
  هنوز مشخص نشده است. رابط، چاپ، بکاپ/بازیابی و خود نصاب روی Windows 7
  آزمایش نشده‌اند؛ پذیرش نهایی منوط به تست روی VM است.

اسکریپت verify **بعد از build** اجرا شود؛ SQLite باید برای ABI خود Electron
بازسازی شده باشد. این تست با Electron 22 واقعی روی سیستم سازنده، یک دیتابیس
موقت می‌سازد و ورود، کنترل دسترسی، نوشتن/خواندن پرونده، multipart PDF، مسیر
فایل و توقف امن را بررسی می‌کند. دادهٔ واقعی کلینیک استفاده نمی‌شود.

## محدودیت‌ها و انتشار

- آپدیت خودکار عمداً غیرفعال است. فقط نصاب **Win7** را برای به‌روزرسانی این
  کاربران بدهید؛ خروجی و metadata را در feed نسخهٔ معمولی منتشر نکنید.
- تولید PDF دسکتاپ از Electron و `printToPDF` استفاده می‌کند. endpointهای
  جایگزین تحت وب که Puppeteer لازم دارند در این خروجی پشتیبانی نمی‌شوند.
- CSS با Tailwind 3 و target مرورگر Chromium 108 ساخته می‌شود؛ ظاهر باید
  بررسی شود، به‌خصوص utilityهایی که در Tailwind 4 اضافه شده‌اند.
- appId و نام برنامه با نسخهٔ معمولی مشترک‌اند تا مسیر داده حفظ شود. این دو
  نسخه را هم‌زمان نصب/اجرا نکنید. قبل از جابه‌جایی، بکاپ خارج از مسیر داده بگیرید.
- این برنچ هنگام ایجاد، تغییرات ذخیره‌نشدهٔ موجود را نیز همراه داشت؛ قبل از
  commit، تغییرات قبلی را از تغییرات legacy تفکیک و بررسی کنید.

## شرط پذیرش هر نسخهٔ بعدی

1. ساخت معمولی و `npm run build:win7` هر دو موفق باشند.
2. `node scripts/verify-windows7.mjs` موفق باشد.
3. روی VM ویندوز ۷ SP1 x64: نصب، فعال‌سازی، دورهٔ آزمایشی، ورود، ثبت/ویرایش
   پرونده، یادآوری، تصاویر، PDF گزارش و فاکتور، چاپ، بکاپ/بازیابی و باز کردن
   دوبارهٔ برنامه بررسی شوند.
4. نصب روی نسخهٔ Win7 قبلی با دیتابیس آزمایشی بررسی شود؛ داده و لایسنس حفظ شوند.
5. سناریوی فیچر جدید روی همین VM هم اجرا شود؛ موفق بودن build جای آن را نمی‌گیرد.

تغییر در handlerهای API به‌طور خودکار در bundle قدیمی قرار می‌گیرد. مسیر جدید
با `route.ts` کشف می‌شود. اگر route به Next.js یا قابلیت جدید Node وابسته شد،
باید سازگاری آن صریحاً اضافه شود. تغییر در بخش‌های حساس `electron/main.mjs`
ممکن است عمداً build قدیمی را متوقف کند تا تطبیق سرور/آپدیت دوباره بازبینی شود.
