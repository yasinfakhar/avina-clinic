# سامانه کلینیک شنوایی آوینا

راهنمای استقرار سرویس مجوز در [license-server/README.md](license-server/README.md) قرار دارد.

اطلاعات پرونده‌ها روی همان سروری که برنامه اجرا می‌شود ذخیره می‌شوند. این نسخه برای اجرا با Node.js و دیسک دائمی طراحی شده است و نباید روی محیط‌های بدون فایل‌سیستم دائمی مانند Cloudflare Workers اجرا شود.

## اجرا

نیازمندی: Node.js `>=22.13.0`

```bash
npm install
npm run dev
```

برنامه توسعه روی `http://localhost:5173` در دسترس است.

اجرای production:

```bash
npm run build
npm start
```

## محل اطلاعات

تمام اطلاعات قابل پشتیبان‌گیری زیر پوشه `data/` قرار دارند:

- `data/audiology.sqlite`: دیتابیس SQLite شامل تمام مقادیر پرونده‌ها و مشخصات فایل‌ها
- `data/images/`: تصاویر اصلی و علامت‌گذاری‌شده بیماران
- `data/pdfs/`: PDFهای بیماران

برای تغییر محل ذخیره‌سازی، متغیر `AUDIOLOGY_DATA_DIR` را روی یک مسیر مطلق در دیسک دائمی تنظیم کنید.

اطلاعات نسخه قبلی که در `localStorage` مرورگر بوده‌اند، هنگام اولین باز شدن برنامه به‌صورت خودکار به SQLite منتقل می‌شوند. تصاویر Base64 نیز به فایل واقعی تبدیل می‌شوند و پس از مهاجرت موفق، داده قدیمی مرورگر حذف می‌شود.

## بکاپ

ابتدا برنامه را متوقف کنید تا هنگام کپی هیچ پرونده‌ای در حال ذخیره شدن نباشد، سپس اجرا کنید:

```bash
npm run backup
```

یک کپی تاریخ‌دار از کل `data/` در `backups/` ساخته می‌شود. برای نگهداری خارج از سیستم، همان پوشه تاریخ‌دار را روی هارد یا فضای امن دیگری کپی کنید. محل خروجی را می‌توان با `AUDIOLOGY_BACKUP_DIR` تغییر داد.

برای بازیابی، برنامه را متوقف کنید، پوشه `data/` فعلی را کنار بگذارید و محتوای بکاپ موردنظر را جایگزین آن کنید.

## نسخه دسکتاپ Electron

در حالت توسعه، رابط وب با `npm run dev` اجرا می‌شود. برای اجرای پوسته Electron توسعه از دستور زیر استفاده کنید؛ اگر تنظیمات سرویس مجوز وجود نداشته باشد فقط نسخه توسعه از مرحله فعال‌سازی عبور می‌کند:

```bash
npm run desktop:dev
```

نسخه نصب‌شده اطلاعات را در پوشه `userData/data` سیستم‌عامل ذخیره می‌کند و به مسیر نصب وابسته نیست. در ویندوز این مسیر معمولاً زیر `%APPDATA%/Avina Audiology/data` است. انتقال فایل مجوز به رایانه دیگر به‌دلیل تطبیق اثر انگشت دستگاه پذیرفته نمی‌شود. فایل‌های پزشکی رمزگذاری نشده‌اند و باید دسترسی سیستم‌عامل به این پوشه محدود باشد.

### قرارداد سرویس مجوز

`POST /v1/activations` این بدنه را دریافت می‌کند:

```json
{"licenseKey":"...","machineFingerprint":"sha256...","appVersion":"1.0.0","platform":"win32-x64"}
```

پاسخ موفق باید شامل `token` با قالب JWS فشرده و امضای Ed25519 باشد. payload باید حداقل شامل `status: "active"`، `machineFingerprint`، `licenseId` و `deviceId` باشد.

`POST /v1/password-recovery/verify` بدنه شامل `code`، `machineFingerprint` و `activationToken` را دریافت می‌کند. پاسخ موفق باید `recoveryToken` امضاشده با `purpose: "password-recovery"`، همان `machineFingerprint` و زمان انقضای `exp` برحسب ثانیه Unix داشته باشد.

### ساخت نسخه ویندوز

برای بررسی محلی ساختار برنامه بدون امضا:

```bash
npm run build:desktop:dir
```

برای ساخت NSIS امضاشده، متغیرهای زیر الزامی‌اند و دو URL باید HTTPS باشند:

ابتدا `.env.desktop.example` را به `.env.desktop` کپی و مقادیر آن را تکمیل کنید. دستور `npm run release:windows -- x.y.z` این فایل را به‌صورت خودکار بارگذاری می‌کند.

- `INITIAL_ADMIN_PASSWORD`
- `LICENSE_SERVICE_URL`
- `LICENSE_PUBLIC_KEY` (کلید عمومی Ed25519 با قالب PEM)
- `UPDATE_BASE_URL`
- `CSC_LINK`
- `CSC_KEY_PASSWORD`

سپس `npm run build:desktop` را اجرا کنید. خروجی در `release/` ایجاد می‌شود. فایل نصب، blockmap و `latest.yml` را بدون تغییر در مسیر عمومی `UPDATE_BASE_URL` قرار دهید. اطلاعات بیمار و تنظیمات در به‌روزرسانی حذف نمی‌شوند.
